# Competitive SEO audit deliverable

Use this reference after competitor discovery when the user asks for a full audit, strategy, roadmap, report, or implementation plan.

## Required sections

### 1. Executive diagnosis

Lead with why the target is or is not being surfaced for the tested intent. Distinguish crawl/index problems, relevance and category-language gaps, content/intent coverage gaps, authority and external-corroboration gaps, page-experience or technical problems, and missing data that requires Search Console, analytics, or a paid dataset.

State what a search engine or AI system would likely think the target is based only on the current live site.

### 2. Current target audit

Inspect the live site, not a remembered version: metadata and headings, visible copy and above-fold message, navigation and internal links, URL architecture and content pages, canonical/robots/sitemap/hreflang/indexability/redirects/404 behavior, social metadata, matching JSON-LD, image semantics, mobile/CWV when measurable, keyword/intent ownership, entity clarity, and only discoverable external authority evidence.

### 3. Discovered competitor matrix

For every direct competitor, report discovery queries/clusters and confidence, homepage title and H1, primary positioning, important landing pages and content structure, internal linking and structured data, market/language fit, publicly discoverable authority signals, why it ranks or is cited, and useful gaps the target can address without copying.

List indirect substitutes and SERP owners separately.

### 4. Keyword and topic map

Group topics by high-intent/commercial, informational/problem-aware, comparison/alternative, use-case/industry, branded/navigational, long-tail/answer-shaped, and local-language/English intent. Name the recommended page owner, flag cannibalization and unsupported demand, and never invent volume.

### 5. Semantic and entity gap

Explain what competitors state more clearly or corroborate more strongly: category, audience/use case, mechanism/differentiators, evidence/trust, schema consistency, About/contact/author identity where appropriate, external mentions/aliases, and answer-ready visible content.

Use current official guidance for Google and other search/AI crawlers. Do not claim special AI markup is required unless an authoritative source says so.

### 6. Recommended architecture

Show the smallest useful architecture across the homepage/category owner, commercial pages, distinct use cases, guides/comparisons, proof/original research, and trust pages. Do not create a route for every synonym; each page needs a distinct task, audience, use case, or information gain.

### 7. Prioritized roadmap

Use P0–P3. Every item includes current problem, evidence, why it matters, change, exact page/system, expected impact, and dependency/owner when business input, credentials, data, outreach, or deployment authority is required.

### 8. Content opportunities

Prioritize a small first batch based on real intent and gaps. For each page provide URL, primary and secondary topics, title/H1, useful outline and required original evidence, internal links, CTA, and why it is distinct. Customer stories, data, reviews, and event media are evidence-gated and never fabricated.

### 9. Exact implementation scope

Before major changes, list exact pages/files/components and intentional exclusions. When implementation was requested, proceed with high-confidence in-scope work after the handoff unless a decision materially changes the product or needs new authority.

### 10. Validation and limitations

Verify as applicable: build/typecheck/lint/tests, status codes/routes, rendered metadata/canonicals/hreflang/headings, robots/sitemap, JSON-LD syntax and visible parity, internal links, mobile overflow, and current performance when the proper tool is available. Report every unverified item and keep local, deployed, submitted, and live states distinct.

## Recommended report shape

Lead with a concise decision brief, then current diagnosis, automatically discovered competitors, semantic gaps, keyword opportunities, architecture, P0–P3 roadmap, exact implementation/validation, and a query/evidence/source appendix.

Create DOCX/PDF or another designed artifact only when the user asks for a downloadable report or the selected workflow explicitly requires one. Reports must be readable, free of invented metrics, and clear about live versus local/un-deployed state.
